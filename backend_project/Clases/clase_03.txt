
1. Para trabajar el getById necesitamos modificar la ruta para que pueda recibir un ID y asi obtener un auto especifico. Por lo que colocamos la referencia
al id. ID tiene que ser como una especie de variable a la cual se le asigna un valor, entonces para que tome el ID como variable, le colocamos ":" antes para
crear un parametro de ruta. Podemos aplicar lo mismo para las demas funciones que trabajen con ID.
2. En el controller, establecemos como parametros un request y un response. Indicamos que vamos a obtener un auto desde el service, pero a dicha funcion le pasamos
la request. La request posee las siguientes propiedades:
    - body: Puede viajar el objeto que manda el front para insertar en una DB.
    - header: Puede viajar un token para login. 
    - params: Hace referencia a los parametros que puede tener una ruta, como por ejemplo, id, name, email, categoria, etc. Al ser un objeto, vamos a tener los
    parametros establecidos.
En este caso el unico parametro establecido es el ID. En las rutas llega el objeto de peticion, el cual es el ID, y pasa al controlador. El controlador recibe 
el objeto de peticion (request) y se lo pasa al service para que pueda extraer el ID.
FInalmente retornamos el auto obtenido como JSON.
3. EL service recibe el objeto de peticion, y se extrae el ID de desde dicho objeto. Luego, con dicho ID obtenemos el auto desde la coleccion de autos en la DB,
pero en este caso buscamos por ID, utilizando el ID extraido. Se añaden algunas validaciones y por ultimo se retorna el auto para que pueda ser accedido por el
controlador.
4. Podemos desestructurar la requeste en el controller para evitar pasar todo el objeto de request al service y solo pasar el ID.
Antes:

cars.controller.js:

    const getCarByIdController = async (request, response) => {
        const car = await getCarByIdService(request);

        response.json(car);
    }

cars.service.js:


    const getCarByIdService = async (request) => {
        const id = request.params.id;

        const car = await Car.findById(id);

        if(!car){
            return {message: "Car not found", statusCode: 404}
        }
        
        return car;
    }

Despues con la desestructuracion:

    const getCarByIdController = async (request, response) => {

        const {id} = request.params;

        const car = await getCarByIdService(id);

        response.json(car);
    }

cars.service.js:


    const getCarByIdService = async (id) => {

        const car = await Car.findById(id);

        if(!car){
            return {message: "Car not found", statusCode: 404}
        }
        
        return car;
    }

5. Para ejecutar la funcion addCar y hacer un POST, necesitamos el objeto que viene en el body. En el controller indicamos que se acceda al body de la
request, y de ahi se extrae el nuevo auto que se pasa al front. Luego se ejecuta el service, pasandole el nuevo auto que se obtiene desde el front. FInalmente
se responde con un mensaje, que es el que se mostraria en el frontend, indicando si se puedo crear el auto que se agrego o no.
6. En el service recibimos ese auto y se lo queremos pasar a la DB. Se abre un try - catch. En caso de que salga todo mal mostramos un mensaje de error. Pero, 
si esta todo bien, al auto lo convertimos en un objeto mongo, ya que es un objeto JS actualmente. Entonces, se indica que el nuevo auto va a estar basado en una
instancia de la coleccion Car, basado en el objeto auto que llega como request. ENtonces:
    car recibido -> Objeto JS.
    Car(car) -> Objeto Mongo.
Pasamos el auto obtenido a traves del modelo (Model) de car que creamos. BAsicamente se crea una nueva instancia del modelo Car, basado en el objeto JS, y se crea
un objeto Mongo.
Para guardar en la DB usamos la funcion save, y finalmente se retorna el mensaje de que se pudo crear el auto correctamente.
7. En el archivo server añadimos;
    app.use(express.json())  
Esto nos perimte leer el body de las peticiones.

8. Para el caso de updateCar, es una combinacion de los dos antetiores porque necesitamos el ID para ubicar el elemento a editar, y luego vamos a extraer datos 
del objeto nuevo para modificar las propiedades del objeto que ya existe en la DB.
9. En el controler, extraemos el ID del request y obtenemos el body del request, el cual contiene los nuevos datos del auto para actualizar. 
10. Llamamos al service y le pasamos el id y los datos del auto para actualizar. Y obtenemos un mensaje, el cual se retorna indicando si se actualizo el auto 
correctamente o no.
11. En el service, programamos un try - catch. Primero se debe encontrar el auto por ID, en caso de que no se encuentre se tira un mensaje de error.
12. Se actualizan las propiedades mapeando cada propiedad del auto encontrado con las del auto pasado en el request. La propiedad isNewCar podria no existir
si no la pasa el usuario, ya que si no lo pasa, por defecto es false segun lo establecido en el model. Entonces, si el request posee la propiedad isNewCar,
se la actualiza al auto de la DB, pero si no la trae, se deja la que tiene el de la DB.
13. Guardamos los cambios con la funcion save, y se envia el mensaje de que el auto se actualizo correctamente.
